Regras de permissão

O que sempre pode, o que pergunta e o que nunca

.claude/settings.local.json

{
  "permissions": {
    "allow": ["PowerShell(az account show)"],
    "ask": ["PowerShell(git push *)"],
    "deny": ["Read(./.env)"]
  }
}

deny: nunca

É conferida primeiro e vale em qualquer modo, até no auto.

ask: pergunta antes

Para o que pode, mas merece um olhar seu.

allow: sem perguntar

Para o que é seguro e repetido.

Onde mora decide para quem vale: ~/.claude você · .claude/settings.json a equipe · settings.local.json só você, aqui · gerenciada: a TI, e vence todas.

Leia mais: guia/03-permissoes-plan-mode-e-rewind.md · No Windows, use PowerShell(...), não Bash(...).

Demo: no segundo terminal, grave o deny de Read(./.env) no .claude/settings.local.json. No Claude, /permissions e mostre a regra em Deny, com a origem. Peça para ler o .env com a ferramenta de leitura: ele é barrado. Peça "Rode no terminal: Get-Content .env": também é barrado. Crie o leitor.ps1, que lê o .env por dentro, e peça para rodar: passa. Feche com "regra não é muro": ela vê a chamada, não o que o script faz por dentro. Para o que nunca pode acontecer, são três proteções: permissão mínima, regra e hook. Limpe apagando o settings.local.json e o leitor.ps1.
